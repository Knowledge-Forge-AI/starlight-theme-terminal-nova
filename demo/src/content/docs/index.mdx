## What you get

Terminal Nova pairs system-sans reading prose with monospace navigation and code boundaries. The
theme plugin supplies package-local styles, a framed page title, a responsive sidebar, card-style
pagination, local middleware, and light/dark code presentation. Your Starlight content, routes,
component overrides, and custom CSS remain consumer-owned.

## Quick start

Install the published peer versions and theme together in an Astro Starlight project:

```sh title="Terminal: install the published package"
npm install astro@7.3.3 @astrojs/starlight@0.42.0 @knowledge-forge-ai/starlight-theme-terminal-nova@0.5.0
```

If your environment deliberately disables package installation scripts, the same package can be
installed with `--ignore-scripts`:

```sh title="Terminal: install without package scripts"
npm install --ignore-scripts astro@7.3.3 @astrojs/starlight@0.42.0 @knowledge-forge-ai/starlight-theme-terminal-nova@0.5.0
```

Register the plugin in `astro.config.mjs`:

```js title="astro.config.mjs"
import { defineConfig } from 'astro/config';
import starlight from '@astrojs/starlight';
import terminalNova from '@knowledge-forge-ai/starlight-theme-terminal-nova';

export default defineConfig({
  integrations: [
    starlight({
      title: 'My Documentation',
      plugins: [terminalNova()],
    }),
  ],
});
```

The plugin takes no accent or family argument at runtime. Continue to [Getting
Started](/docs/getting-started/) for custom CSS, component overrides, and a consumer checklist.

<Aside type="tip" title="Choose the target that matches your site">

Use STTN when your product is an Astro Starlight documentation site. Choose CTTN when the target
is a shadcn/Tailwind application. Nebular is the authoring and preview surface for shared Theme
Forge work; it is not required to build or serve STTN documentation.

</Aside>

## Published package and family previews

The published 0.5.0 package keeps the unchanged Forge Console design (as in 0.4.0, regenerated):
warm orange roles, Starlight navigation and code presentation, local middleware, and consumer-owned
CSS and component overrides. The 0.4.0 release is historical package context, not the current
installation target.

The package also publishes six opt-in family stylesheets under
`styles/appearances-sttn/`: `terminal-nova`, `nebular`, `developer`, `graphic-designer`, `anime`,
and `gamer`. Adding one stylesheet is an explicit consumer choice; `terminalNova()` still has no
runtime family argument, picker, persistence, or save/reopen workflow.

This demo's gallery provides six families × two static Starlight routes. Its controls navigate
among prebuilt specimens and do not turn the package into a runtime selector. The gallery is a
separate demo review surface alongside the package stylesheets; this guidance does not assert byte
identity between route assets and package tar members. The specimens retain the documented
component-boundary differences, so the gallery is not a claim of final native or visual
qualification.

| Capability | Published 0.5.0 | Demo / preview boundary |
| :--- | :--- | :--- |
| Astro/Starlight integration | `astro@7.3.3` and `@astrojs/starlight@0.42.0` consumer baseline | Future site or package revisions may broaden the tested range |
| Primary appearance | Unchanged Forge Console design (0.4.0, regenerated) with orange accent | Demo gallery is a separate static review surface |
| Family stylesheets | Six opt-in published package CSS files | Twelve static family/mode specimen routes |
| Alternate accent | Cyan output selected during generation | Not a runtime `terminalNova({ accent })` option |
| Navigation and code chrome | Nested sidebar, card pagination, framed title, expressive code defaults | New catalog composition is maintained separately from this content slice |
| Family selection and persistence | No runtime picker or persisted choice | Gallery controls select a prebuilt static route only |
