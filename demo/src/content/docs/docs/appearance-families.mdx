## One family, two appearances

A family combines its palette, type, surfaces and geometry. Light and dark are the two sides of
that family. The site's Auto mode follows your system; each separate specimen has an explicit light
or dark choice. Switching it does not compile anything or contact an external service.

Terminal Nova keeps its cyan, orange and amber vocabulary. Nebular explores purple work surfaces
and gold highlights. STTN 0.5.0 publishes all six family stylesheets as opt-in package resources;
this site separately provides twelve static specimen routes so readers can compare a fixed light or
dark specimen without changing the site's own preference.

The gallery controls select prebuilt routes, and each frame is sandboxed so its scripts and storage
remain separate from the parent site. This is a separate static demo review surface alongside the
published package stylesheets; it does not assert byte identity between route assets and package tar
members. It is not a runtime picker, persisted preference flow, or claim of final native or visual
qualification.

## Shared intent, different components

STTN maps the intent to Starlight navigation, reading layouts, code and documentation components.
CTTN maps the same intent to Tailwind and shadcn components. These targets need different CSS and
component behavior; their outputs are not expected to be pixel-identical. Not every semantic leaf
is mapped in this preview: some Starlight surfaces still retain the existing Forge Console
template, and code syntax keeps its current presentation. Those differences remain visible so
they can be evaluated accessibly rather than being treated as completed mappings.

The Anime and Graphic Designer v2 profiles request serif headings, but the current STTN adapter
marks that heading-family leaf as unsupported and emits its existing system-monospace heading
stack. The preview therefore records the intent without presenting that leaf as a completed target
mapping.

The specimens retain the current Starlight header and sidebar heredity while dedicated
family-specific component roles are still being mapped. This keeps navigation and orientation
familiar without implying that every component role has a finished family treatment.

Each static variant page exposes the exact v2 source profile used for that demo specimen. The
download is a review and handoff input; it does not add family editing, persistence, or runtime
selection to the published STTN plugin.

Appearance choices affect interface surfaces. They do not recolor protected identity artwork or
change a document being authored in Nebular. The existing Terminal Nova mark keeps its approved
light and dark treatments.

## Use the published theme

Follow [Getting Started](/docs/getting-started/) to install STTN 0.5.0 and integrate its Starlight
plugin. Add one published family stylesheet explicitly when a consumer site needs it; the plugin
itself takes no family option. [Engine Workflow](/docs/workflow/) explains generation and
customization; [Component Gallery](/docs/components/) shows the documentation components.

See [Brand and License](/docs/brand-and-license/) for the distinction between software and official
identity artwork. Source is maintained on [GitHub](https://github.com/Knowledge-Forge-AI/starlight-theme-terminal-nova),
with published packages on [npm](https://www.npmjs.com/package/@knowledge-forge-ai/starlight-theme-terminal-nova).
