## Prerequisites

Use the published baseline below for the documented adoption path:

| Package | Version |
| :--- | :--- |
| Node.js | `>=22.12.0` |
| Astro | `7.3.3` |
| `@astrojs/starlight` | `0.42.0` |
| `@knowledge-forge-ai/starlight-theme-terminal-nova` | `0.4.0` |

Terminal Nova's package declares compatible Astro and Starlight peer ranges, but pinning the
versions above gives a reproducible starting point for the current public instructions. The theme
is a Starlight integration; it does not replace Astro or Starlight.

The source tree also carries the 0.5.0 package metadata candidate. It is not published to npm yet,
so the install commands below intentionally remain on the published 0.4.0 baseline.

## Install the published package

From an existing Astro project, install the peer versions and theme:

```sh title="Terminal: install published Terminal Nova 0.4.0 baseline"
npm install astro@7.3.3 @astrojs/starlight@0.42.0 @knowledge-forge-ai/starlight-theme-terminal-nova@0.4.0
```

If your package policy disables lifecycle scripts, use the same versions with `--ignore-scripts`:

```sh title="Terminal: install with scripts disabled"
npm install --ignore-scripts astro@7.3.3 @astrojs/starlight@0.42.0 @knowledge-forge-ai/starlight-theme-terminal-nova@0.4.0
```

The package is also available from [npm](https://www.npmjs.com/package/@knowledge-forge-ai/starlight-theme-terminal-nova)
and its source is in the [Terminal Nova repository](https://github.com/Knowledge-Forge-AI/starlight-theme-terminal-nova).

## Register the plugin

Add the plugin to the Starlight integration in `astro.config.mjs`:

```js title="astro.config.mjs"
import { defineConfig } from 'astro/config';
import starlight from '@astrojs/starlight';
import terminalNova from '@knowledge-forge-ai/starlight-theme-terminal-nova';

export default defineConfig({
  integrations: [
    starlight({
      title: 'Example Documentation',
      description: 'Product documentation with Terminal Nova.',
      plugins: [terminalNova()],
      sidebar: [
        {
          label: 'Documentation',
          items: [
            { label: 'Welcome', slug: 'index' },
            { label: 'Getting Started', slug: 'docs/getting-started' },
          ],
        },
      ],
    }),
  ],
});
```

`terminalNova()` has no runtime configuration object. The plugin installs its package styles,
default theme components, route middleware, and Expressive Code defaults while preserving explicit
consumer settings.

:::tip[Keep the content tree yours]

The sidebar above is a consumer choice. Add your own groups and routes rather than copying the
demo's navigation wholesale. The theme changes presentation, not the information architecture of
your product.

:::

## Add approved identity assets when needed

If a site uses the supplied Terminal Nova marks, place the exact approved files in a consumer-owned
`public/brand/` directory and select the light or dark treatment for its surface:

```js title="astro.config.mjs: optional logo and favicon"
starlight({
  logo: {
    light: './public/brand/theme-forge-terminal-nova-mark-on-light.svg',
    dark: './public/brand/theme-forge-terminal-nova-mark-on-dark.svg',
    replacesTitle: false,
  },
  favicon: '/brand/favicon-on-light.svg',
});
```

Use a dedicated favicon at small sizes. Do not recolor, redraw, filter, or decorate a protected
mark through ordinary accent tokens, and do not imply endorsement. Read [Brand and
License](/docs/brand-and-license/) before distributing identity artwork.

## Customize without copying generated styles

The theme's package CSS loads before your `customCss` entries. Start with a focused consumer rule:

```css title="src/styles/site.css"
:root {
  --tfsl-color-accent-base: #69d3e4;
  --tfsl-color-focus: var(--tfsl-color-accent-base);
}

.sl-markdown-content a:focus-visible {
  outline: 2px solid var(--tfsl-color-focus);
  outline-offset: 3px;
}
```

Register the file in Starlight:

```js title="astro.config.mjs: custom CSS"
starlight({
  customCss: ['./src/styles/site.css'],
});
```

The published package already defines light and dark roles. A local override should preserve
readability and visible focus in both modes; do not assume a single color works on every surface.

## Override a component deliberately

When a site's title treatment or metadata needs a different layout, use Starlight's component map:

```js title="astro.config.mjs: component override"
starlight({
  components: {
    PageTitle: './src/components/ConsumerPageTitle.astro',
  },
});
```

An explicit consumer mapping takes precedence over Terminal Nova's default `PageTitle` component.
Keep the override in your source tree so it is reviewable and replaceable when Starlight changes.

## Published behavior and preview boundaries

The still-published 0.4.0 package uses the Forge Console design with the orange primary accent. Cyan is an
existing alternate output selected during generation; it is not a runtime `accent` option passed
to `terminalNova()`. The shared next-cycle collection contains six visual families with light and
dark appearances, but it is still development work. The published package does not ship all six
families, a twelve-entry runtime picker, or persisted family selection.

For the relationship to the other Theme Forge products, see [Architecture
Overview](/overview/) and [Engine Workflow](/docs/workflow/). STTN is the Astro/Starlight target;
CTTN is the sibling shadcn/Tailwind target; Nebular Fusion is the desktop authoring and preview
workbench.

<Aside type="caution" title="When the theme is not visible">

Check that the package is installed at the published `0.4.0` baseline, the plugin is present in the `starlight({ plugins
})` array, and the consumer is actually using the intended Astro configuration. If a consumer
override is too broad, temporarily remove it to isolate the site rule from the package default.

</Aside>
